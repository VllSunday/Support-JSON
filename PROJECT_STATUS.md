# Состояние проекта

Публичный выпуск: [модель и исходники демки](https://huggingface.co/A11Sunday/support-json-qwen3.5-4b-lora), [датасет](https://huggingface.co/datasets/A11Sunday/support-json-ru). README содержит инструкции запуска и анимированное видео реального приложения; обновлённые материалы сдачи собраны в архив v3. Лицензии: Apache-2.0 для кода и адаптера, CC BY 4.0 для данных. Подробности публикации и проверок скачивания — `reports/hf-*.json`.

Обновлено 18 сентября 2026. Учебный capstone собран: три LoRA-прогона и validation, финальный test 108, дополнительный few-shot контроль, содержательный AI-assisted аудит, экспорт и самостоятельный запуск адаптера, локальная демка и презентация. Выбран третий адаптер. Работа завершилась после полуночи. Домен SaaS; задача — помощь оператору, без исполнения операций.

После основного эксперимента интерфейс обновлён по пользовательскому макету Open Design. Добавлены локальные шрифты, форматирование и копирование JSON, визуальное отображение источников фактов и редакторы контекста. Поведение проверено отдельными реальными запросами и в браузере; веса, инструкции модели и основной benchmark не менялись. Подробная проверка формальных требований и остаточных ограничений: [TZ_AUDIT.md](docs/TZ_AUDIT.md). Отсутствие ошибок текста и реальная экономия времени операторов не доказаны.

## Очерёдность

1. Проверка пилотных правил и короткой выборки, токенизация и loss masking.
2. Исходная модель на validation: получить первую точку отсчёта.
3. Один небольшой запуск LoRA, затем то же сравнение на validation.
4. Исправление данных по ошибкам, расширение и фиксация эксперимента.
5. Сравнение на отдельном test, ручная оценка ответов.
6. Локальная демка, экспорт, model card, презентация и оценка бизнес-пользы.

## Журнал

- Экспорт проверен: девять файлов соответствуют манифесту; веса идентичны выбранному checkpoint, ревизия базы фиксирована. Самостоятельный predict.py успешно выполнил реальный CUDA inference с валидным контрактом.
- Локальная демка с экспортом: 12 корректных HTTP-статусов, 8/10 совпадений ожидаемых полей вместе с контрактом. Ошибочный отказ при выполненном условии и ошибочный action при missing_info сохранены. Отдельное чтение текста отмечает ещё неточное изложение границы срока и выдуманный внешний статус возврата. Это дополнительная validation-derived выборка, не независимый test и не основание для изменения модели.
- В браузере проверены настоящий ответ, очистка фактов/истории/результата при смене обращения, скрытие запоздалого ответа, ошибка JSON и две responsive-компоновки. Временный размер viewport сброшен.
- Дополнительный base + четыре замороженных train-примера: test 108, действие отдельно 40,7%, приоритет 77,8%, контракт 76,9%. Основное сравнение base/LoRA использует одинаковый промпт; этот контроль имеет другой промпт и batch 4, не является сравнением с сильной крупной моделью.
- Презентация проверена после импорта итогового PPTX: 10/10 полноразмерных рендеров просмотрены; native tables сохранены. Структурная и геометрическая проверки пройдены. Работа PowerPoint на другом устройстве не проверена.

- Итоговый test 108: категория отдельно 76,9% → 100%, приоритет 72,2% → 99,1%, действие 27,8% → 89,8%, схема и инварианты 54,6% → 95,4%, critical recall 0/3 → 3/3. Тест маленький и синтетический; не доказана работа с любыми компаниями. Ответы и отпечатки сохранены.
- AI-assisted содержательный аудит 36 пар завершён с отдельными объяснениями всех 72 оценок. У LoRA пять ложных утверждений о фактах/политиках; правильный JSON не гарантирует правильный reply. Независимая человеческая оценка отсутствует.
- Пользователь сообщил о падении FPS в параллельной игре и попросил продолжить проект. Дополнительный контроль batch 8 перезапущен целиком на batch 4 с освобождением неиспользуемой CUDA-памяти. Первые 24 ответа сохранены как aborted-batch8; промпт и четыре train-примера не менялись по качеству. Основной benchmark уже завершён и не меняется. Задержки общей desktop-сессии не называются изолированным тестом производительности.
- Третий validation (96): правильное действие отдельно 89,6%, полный контракт 95,8%, категория и приоритет отдельно 97,9%, critical recall 3/3. Второй адаптер имеет более высокий контракт (99,0%), но хуже решение (78,1%). По заранее заданному порядку выбран третий; этот компромисс сохраняется в отчётах. Test открыт после записи выбора.
- Третий LoRA завершён: 512 примеров × 2 эпохи, 128 обновлений, train loss 2,6425 → 0,0309, около 14 минут. Это не оценка качества; запущен validation на тех же 96 отделённых обращениях.
- Второй validation (96): категория отдельно 96,9% → 100%, приоритет 71,9% → 96,9%, действие 28,1% → 78,1%, соответствие схеме и инвариантам 49,0% → 99,0%. Critical recall 2/3 → 3/3; это лишь один сценарий с тремя эмоциональными формулировками. Остались ошибки решений по правилам, поэтому идеальность не заявляется.
- Третий эксперимент v0.5: исходные 192 плюс 320 новых записей, разные ключи фактов и условия отдельных доменов вместо одного универсального шаблона. Это проверка гипотезы о разнообразии данных, а не обучение всех 10 000 кандидатов. Batch 2 × accumulation 4 помещается в GPU; две эпохи и 128 обновлений.
- До test зафиксировано ограничение выбора: critical recall на validation не ниже base. Среди прошедших — максимум правильных действий, затем контракт, приоритет и категория. После открытия test новые настройки по его результатам не подбираются.
- Исправлен интерфейс: изменение обращения очищает старые факты и результат; ответ устаревшего запроса не подставляется после изменения входных данных. Проверка синтаксиса пройдена; браузерная проверка нового перехода и реального модельного ответа ожидается после GPU-экспериментов.
- Второй LoRA успешно завершён: 1024 примера, 128 шагов, loss 2,644 → 0,044; журнал и SHA256 адаптера в reports/training-expanded-v4.json. Начат validation того же замороженного набора из 96 обращений.
- До открытия финального test зафиксированы четыре образца из исходного train (refund true/false, cancellation unknown, technical critical). Дополнительный base few-shot контроль выполняется после основного сравнения; настройки по test не меняются. Он не подменяет основное сравнение с одинаковым промптом.
- Первый validation сравнения (96): контракт 49% → 90%, действие отдельно 28% → 61%, категория отдельно 97% → 88%, приоритет отдельно 72% → 82%. Critical recall: base 2/3, первый LoRA 0/3; три строки — эмоциональные варианты одного критического сценария. Полные необработанные прогнозы и метрики сохранены. Это существенная регрессия, не скрытая общим улучшением.
- Второй LoRA выполняется с нуля от той же базы на 1024 записях. В них 58 critical вместо трёх в исходном train; все семь категорий представлены. Данные зафиксированы до результатов первого сравнения; их составление опиралось на постановку задачи, а не на test.
- BF16 LoRA через Soup/Transformers/Liger завершён: 223,6 с, 24 обновления, loss 2,607 → 0,249. Адаптер 129 927 008 байт, SHA256 и журнал зафиксированы в reports/training-pilot-v3.json. Это измерение train-loss, не качества ответа.
- Исходная Qwen на 96 validation: 100% JSON разбираются, 49% соответствуют схеме и инвариантам, 21% действий правильны. При нарушении контракта все поля задачи считаются ошибочными; raw field accuracy отдельно не заявляется.
- Установлен и проверен Liger: первый запуск без него остановлен до первого обновления из-за переноса GPU-памяти в RAM. Успешное обучение с fused linear cross entropy прошло без этого переноса.
- Исправлена остановка генерации на обоих штатных EOS: один из model config, другой из tokenizer. Именно эта одинаковая конфигурация используется для полного сравнения; ранние smoke-тесты не являются финальным baseline.
- Расширение v0.4: 10 000 синтетических train-кандидатов, 5685 смысловых групп. Для второго эксперимента — 1024; 1024/1024 проходят реальную маску Soup без обрезаний. Лицензия публикации не назначена, человеческое подтверждение отсутствует.
- scripts/continue_experiment.py последовательно запускает второй LoRA, validation, выбирает адаптер по validation и только затем сравнивает base/LoRA на test. Два GPU-запуска одновременно не выполняются.
- По запросу пользователя включён непрерывный цикл выполнения полного capstone. Цель — завершить сегодня; обучение и скачивание весов разрешены. Длительность реальных прогонов ещё не измерена.
- Установлен PyTorch 2.11.0+cu128. CUDA и BF16-умножение проверены на RTX 5070 Ti (16 ГБ).
- Все 192 записи прошли проверку фактической маски Soup: контекст исключён из loss, ответы и EOS включены. Подготовлена native-конфигурация Transformers, без квантизации, с лимитом 2048.
- Все веса фиксированной ревизии Qwen3.5-4B скачаны. SHA256 обоих файлов совпали с Hugging Face.
- Исходная текстовая Qwen3_5ForCausalLM загружена на GPU за 6,3 с, занимает около 7,83 ГиБ по счётчику PyTorch. Baseline выполняется. На Windows используются эталонные PyTorch-операции DeltaNet; ускоренные FLA/causal_conv1d не установлены.
- Форма локальной демки и ошибки JSON проверены в браузере и через HTTP. Сервер остановлен на время экспериментов, чтобы исключить конкурирующую загрузку модели.
- Диагностика исходного промпта: четыре обращения одной категории, 0/4 соответствуют выходному контракту; модель копирует JSON Schema. Это smoke test, не общая оценка качества.
- На validation уточнена инструкция о заполнении полей; train переэкспортирован в pilot-v0.3 без изменения эталонов. Исходный промпт сохранён в docs/prompts/system-v0.2.txt. Test не использован для этой правки.
- Добавлены Triton Windows 3.6.0.post26 и FLA 0.5.2. GPU-проверка FLA: совпадение с PyTorch в допуске (максимальная ошибка 0,00049), обратный проход конечный. Первый запуск с исправленной инструкцией и FLA выполняется.

- Исследование источников сохранено в output/research. Готового универсального русского корпуса не найдено среди проверенных кандидатов.
- Создан Python-проект и отдельное окружение. Установлен лёгкий Soup 0.75.0; обучение не запускается при подготовке данных.
- Пилот v0.1: 336 строк. Выявлено неполное покрытие категорий и приоритетов validation.
- Пилот v0.2: 396 строк; train 192, validation 96, test 108. Все семь выбранных категорий и четыре приоритета представлены в каждой части. 96 косметических дублей удалены.
- Проверка счётчика на эталонах — технический selfcheck, не результат модели.
- Проверки: 19 тестов пройдены; Soup принимает YAML и 192/192 записей ChatML; pip check не выявил конфликтов зависимостей.
- Токенизатор исходной Qwen3.5 проверен без загрузки весов: максимальная полная последовательность 1039 токенов, обрезаний при лимите 4096 нет. Ревизия токенизатора и шаблон сохранены в reports/tokenizer-preflight.json.

## Существенные ограничения

Синтетические шаблоны ещё не отражают разнообразие реальных переписок. В test только одна компания и одно критическое состояние с тремя тонами. Разделение по авторским семействам не заменяет независимую проверку смыслового сходства. Улучшение показано на отдельном test, но ошибки текста и следования правилам остаются. Независимая человеческая оценка, перенос на произвольные правила, готовность к автономному запуску и цель скачиваний на Hugging Face не подтверждены. Публикации не было. Более ранние строки журнала описывают состояние на момент события; актуальные результаты приведены сверху.
