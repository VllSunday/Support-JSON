# Проверка соответствия capstone

Проверено 18 сентября 2026 по исходному заданию «AI Customer Support Manager» из пользовательского вложения. Домен — SaaS. Проверка различает наличие выполненной работы и качество поведения модели: реализованная функция не означает отсутствие ошибок.

**Вывод:** основной учебный эксперимент и пять запрашиваемых результатов подготовлены. Дообучение улучшило показатели на отдельном синтетическом test. Однако заявить полное выполнение требования «не содержать выдуманной информации» нельзя; фактическая экономия времени операторов также не измерена. Это прототип помощника с обязательной проверкой ответа человеком, а не готовая автономная поддержка.

## Что показывает эксперимент

На test 108 показатель категории отдельно вырос с 76,9% до 100%, приоритета — с 72,2% до 99,1%, действия — с 27,8% до 89,8%. При требовании валидности всего контракта точность действия — 24,1% → 86,1%; контракт — 54,6% → 95,4%. Эти определения нельзя смешивать.

В содержательном AI-assisted аудите 36 пар качество ответа выросло с 2,78 до 4,31 из пяти; доля ложных утверждений снизилась с 13/36 до 5/36. Это небольшая синтетическая выборка, не доказательство универсальности и не независимый человеческий бенчмарк. Проверка формата JSON не проверяет истинность текста.

Созданы 10 000 train-кандидатов, но выбранный адаптер обучен на 512 примерах в течение двух эпох. Нельзя говорить, что итоговая модель обучена на всех 10 000. Внешние исследованные датасеты в обучение не включались. Разделение по авторским семействам и новые тексты правил не гарантируют отсутствия близких смысловых шаблонов.

## Что ещё нужно для сильной защиты и практического применения

1. Попросить человека проверить небольшую случайную выборку уже сохранённых пар по той же шкале. Это независимая оценка текущего результата, без подбора модели на test.
2. Для фактической бизнес-метрики провести парный замер времени подготовки ответа на одинаковых обращениях: вручную и с помощником, включая проверку и исправление черновика. Сейчас «30 часов в месяц» — расчёт при допущениях, а не измерение.
3. Для следующей модели исправлять данные по ошибкам validation, добавить реальные разговорные формулировки и многоходовые истории; заранее создать новый закрытый test. Текущий test уже изучен и больше не подходит для настройки следующей версии.
4. Перед автономным применением отдельно проверить фактическую корректность ответов, новые правила, конфликты и устойчивость к пользовательским попыткам изменить инструкции. Подключение CRM, RAG и исполнения действий — отдельное расширение, не выполненные функции текущего прототипа.

## Дополнительные функции и границы

История переписки поддерживается на входе демки, но обучающие истории пустые; способность работать с ней недостаточно проверена. Указание источников фактов, неизвестные значения null, недостающие сведения, ссылки на идентификаторы правил и запрет исполнения операций реализованы. Нельзя утверждать поддержку любых правил компании, нулевые галлюцинации или полную защиту от prompt injection.

RAG, confidence score, реальная автоматическая передача оператору, квантизация, DPO / RLHF и Ollama / vLLM / llama.cpp не обязательны исходным ТЗ. Их отсутствие не делает эксперимент невыполненным. Дополнительно опубликованы [адаптер с приложением](https://huggingface.co/A11Sunday/support-json-qwen3.5-4b-lora) и [датасет с четырьмя конфигурациями](https://huggingface.co/datasets/A11Sunday/support-json-ru). Код и адаптер — Apache-2.0, данные — CC BY 4.0. Подтверждение публикации: `reports/hf-publication.json`; цель скачиваний этим аудитом не проверяется.

Первый архив сдачи и презентация фиксируют предыдущий светлый интерфейс. Обновлённый архив v3 содержит текущий тёмный интерфейс и 35-секундное видео настоящего локального прогона. Основной эксперимент, выбранные веса и тестовые прогнозы при обновлении дизайна не изменяются. Видео — монтаж известного validation-примера, не новый независимый тест; ожидание сокращено.
