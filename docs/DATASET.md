# Пилот данных v0.2

396 авторских синтетических примеров. Это инженерный набор для проверки формата и первого эксперимента, не финальный корпус для публичной модели. Чужие датасеты и ответы больших моделей в этот пилот не включены. Для публичного выпуска автор назначил CC BY 4.0: см. `LICENSE.dataset.txt` и карточку `docs/HF_DATASET_CARD.md`. Исторические JSONL-снимки и их хеши сохранены; прежнее значение `not_assigned` в метаданных отражает момент создания, а не лицензию текущего выпуска.

## Структура

- `input.message`, `input.history`: только доступный текст клиента и история.
- `input.policies`: доверенные правила с идентификаторами.
- `input.facts`: значения с происхождением `user_report` или `tool_observation`; `null` означает неизвестное. Подтверждения системы не восстанавливаются из слов клиента.
- `input.capabilities`: только рекомендации, инструментов выполнения нет.
- `target`: category, priority, sentiment, action, recommended_action, reply, missing_info, supported_rule_ids, human_escalation.
- `metadata`: split, company_id, scenario_family_id, scenario_group_id, версия и короткие основания аудита. Модель их не получает.

Схема ответа v0.2 добавляет **конкретное** recommended_action к общему action из первоначального исследования. Например, propose_action + propose_refund. Это нужно для полного соответствия ТЗ.

## Получение эталонов

Авторские правила находятся в `src/support_json/catalog.py`: текст политики, условия, варианты фактов и допустимые действия. Условные операции: равенство, сравнение границ, принадлежность списку, AND/OR, проверка источника. Неполные сведения не превращаются автоматически в ложь. Для AND известное ложное условие снимает необходимость спрашивать остальные; для OR известное истинное исключение достаточно для решения.

Каждое семейство получает выполненное/невыполненное/неизвестное условие и конфликт правил, затем три эмоциональных варианта. Решение считается программно. Настроение задано авторским текстом; приоритет прописан отдельной политикой. Короткие формулировки и ответы сейчас шаблонные — естественный русский и качество ответов ещё нужно проверять.

Проверка JSON и существования rule ids не доказывает смысловую корректность политик. Все записи пока имеют `human_reviewed=false`. Очередь из 64 примеров train/validation покрывает семейства и состояния; включает разные эмоциональные варианты. Тест не входит в очередь настройки разметки.

## Разделение

| Часть | Строк | Компаний | Авторских семейств |
|---|---:|---:|---:|
| Train | 192 | 3 | 8 |
| Validation | 96 | 1 | 8 |
| Test | 108 | 1 | 9 |

Политики и семейства заданы отдельно до генерации. Примеры одного состояния с разным тоном остаются вместе. Из 492 кандидатов удалены 96 дублей, отличавшихся только идентификаторами и компанией. Сравнение выполняется после удаления косметических полей. Аудит запрещает пересечение компаний, обозначенных семейств, групп и полных текстов политик между частями.

Это перенос на новую компанию и авторские варианты правил **в знакомом SaaS-домене**, не доказательство универсальности. Семантическую близость разных авторских семейств всё ещё требуется проверить; совпадение примитивов вроде AND не является утечкой само по себе. Формулировки родственны по стилю, автоматического теста на все смысловые перефразирования нет.

## Ограничения пилота

- Один тестовый бизнес, мало критических случаев: три строки critical в test относятся к одному состоянию с разным тоном. Это не три независимых инцидента.
- Состояния намеренно сбалансированы; 25% конфликтов и почти половина эскалаций не отражают реальные обращения.
- Структурированные факты уже предоставлены приложением. Извлечение фактов из многотуровой истории пока не реализовано.
- Категория other предусмотрена схемой, но не покрыта этим пилотом. Длинные диалоги, опечатки и широкие неоднозначные обращения пока отсутствуют.
- Стандартные ответы не заменяют полноценные полезные объяснения условий; их качество нужно улучшать после анализа базовой модели.

Из частот этого набора нельзя оценивать реальную долю автоматизации бизнеса или обещать продакшн-точность.

## Следующее расширение

После проверки пилота добавить минимальные и избыточные уточнения, несвязанные запросы, исключения с несколькими условиями, реальные разговорные формулировки и историю. Выборочно адаптировать ABCD/ShARC/Doc2Dial после проверки происхождения и лицензии, без скрытых answer/evidence во входе. Языковая генерация может менять текст, но не факты и эталонное решение. Новые версии сохраняются в отдельных папках.
